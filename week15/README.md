# 15주차 — 최종 발표 & 총정리 (기말고사)

✅ 이 주차는 새로운 실습 코드가 없습니다 (기말고사 주간, 8주차 중간고사와 같은 방식). 1~14주차의 결과물 — 팀 프로젝트와 포트폴리오 사이트 — 로 평가합니다.

## 이번 주 진행 방식

- **팀 프로젝트 최종 데모 + 발표** (비중 大) — 8주차에 발표한 기획서를 바탕으로 9~14주차에 실제로 구현한 서비스를 라이브 데모합니다. 최소 다음을 포함해야 합니다: 게시판형 CRUD, Auth.js 기반 인증/RBAC, 12~14주차에서 배운 5종 취약점 중 최소 3종에 대한 방어 코드(직접 구현 또는 왜 해당되지 않는지 설명), 배포 URL(Vercel 등).
- **개인 기여도 보고서** — 팀 프로젝트에서 본인이 실제로 작성한 코드/기능을 커밋 링크와 함께 정리합니다. "누가 무엇을 했는가"를 명확히 하기 위함입니다.
- **포트폴리오 사이트 완성본 제출** (개인) — 8주차 초안을 발전시켜, 1~14주차 과제 링크 모음 + 팀 프로젝트 소개 + 자기소개를 담아 Vercel에 최종 배포합니다.
- 그동안의 과제(#1~11) 커밋 이력, 특히 12~14주차 보안 과제(#9~11)의 재현/수정 이력을 함께 봅니다.

## 발표 & 제출 방법

1. 팀 레포(`team-<팀명>` 권장)에 최종 코드 push + README에 배포 URL, 담당 역할 표 포함
2. [submissions-2026](https://github.com/wss-2026/submissions-2026)에 `submissions/team/팀이름.json`으로 repo_url · commit_sha · deploy_url PR 제출
3. 팀당 8분 데모 + 발표, 5분 질의응답
4. 개인 제출란에 포트폴리오 사이트 배포 URL + 기여도 보고서(A4 1장) 제출
5. submissions-2026에 1~14주차 과제 PR이 모두 올라가 있고 자동채점 결과에 심각한 실패가 없는지 최종 점검

## 평가에서 특히 보는 것 (12~14주차 보안 유닛 연계)

- 팀 프로젝트에 XSS·시크릿 관리·NoSQL Injection·IDOR·Rate Limiting 중 최소 3종을 실제로 어떻게 막았는지 (또는 왜 해당 위협이 없는 구조인지 논리적으로 설명) — 코드와 함께 발표에서 짧게 언급
- `.env.local`, API 키, DB 접속 정보 등이 실제로 레포에 커밋되어 있지 않은지 (시크릿 관리 체크리스트 준수 여부)
- 인증이 필요한 페이지에 실제로 인증/인가 검사가 있는지 (11·13주차 IDOR 패턴 적용 여부)

## 한 학기 되짚어보기

- **1~4주차**: 웹 개발 전체 그림과 Next.js/React/TypeScript/Tailwind/MongoDB/Auth.js 테크스택, File-based Routing과 Server/Client Component 구분
- **5~9주차**: 공지사항 게시판을 in-memory → MongoDB → Auth.js 인증 → RBAC/심층방어까지 단계적으로 발전
- **10~11주차**: 쇼핑몰(카탈로그, 쿠키 장바구니, 주문, 재고 원자적 처리, 가격 스냅샷)로 실전 규모의 기능 구현
- **12~14주차**: OWASP 5종 취약점(XSS·시크릿 관리·NoSQL Injection·IDOR·Rate Limiting)을 직접 만들고 직접 고치며 "정적 분석은 보안 취약점을 잡지 못한다"는 것과 "왜 코드 리뷰·거버넌스가 필요한지"를 체감
- **15주차**: 이 모든 것을 팀 프로젝트와 포트폴리오로 종합
